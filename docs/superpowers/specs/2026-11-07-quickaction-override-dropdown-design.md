# 动作覆盖下拉改造（显示动作名 · 两级可搜索）设计文档

> 日期：2026-11-07 · 作者拍板（会话内四轮截图评审逐条收敛） · 状态：**定稿，已实施并冒烟验证**
> 可视定稿 = `SurvivalLog.ModCenter/prototype.html`（动作覆盖块交互与文案以它为准）。
> 本文档结论已并入 `SurvivalLog.ModCenter/DESIGN.md` §6.1 契约注释与两仓 CHANGELOG
> （ModCenter v2.1.1 / QuickAction v1.8.0，均未发版）。
> **范围纪律（作者令）：只改「动作覆盖」这一块，面板其余部分零改动。**

## 1. 意图与背景

「动作加速」详情页的「动作覆盖（单个动作单独调）」原新增入口是一个 `动作 ID` 手输框 +
「＋新增覆盖」按钮——玩家看不懂动作 ID（作者令 2026-11-07）。同时"哪些动作可加速"的
判定口径（表外结算收益/周期正收益/纯消耗拦 Outside8/瞬时哨兵/禁改类）全部在 QuickAction
引擎内且随版本频繁迭代，ModCenter 不应复算一份必然发散的逻辑。

## 2. 目标 / 非目标 / 反目标

**目标**
- 面板选动作只显示**动作名**，ID 只留在 cfg 对账小字（`其他.Overrides · id:ms`）。
- 下拉**两级 + 可搜索**：先选类型（六组带数量）→ 弹该类型动作列表（搜索框过滤 + 返回类型），
  不全量平铺（作者令四稿）。
- 名单**完整且口径单源**：覆盖写一定生效的动作全部在列（含第 6 组「野外与其他」——引用轴
  漏网的 Other 玩家动作，如 冒险出门 探索中109/搜索/翻找/撬开/瞭望/清点物资，作者令）。
- 每行动作**随时可改**（保留该行毫秒）；尾部恒置一行未设置行，选完自动生效并自动补新空行。

**非目标**
- 不改覆盖的写路径与语义：仍序列化 `"id:ms"` 整串 `MC_SET 其他.Overrides`，C# TrySet 零改动。
- 不改 QuickAction 分类引擎/守卫/开关；目录文件是只读旁路产物。
- 不动面板其余任何块（分类耗时滑条、柜子个性化、维护区等）。
- 睡觉/社交（禁改类）、周期收益类（提速必亏）仍不进目录——非缺失，是语义上不可动。

**反目标（出现即失败）**
- 旧 QuickAction（无目录文件）配新 ModCenter 时面板不可用——必须回退 ID 手输框（已实现）。
- 两 dll 口径漂移：守卫逻辑在 ModCenter 复算一份（必然发散）——目录单源在 QuickAction。
- 目录外旧 ID 串值：兜底显示 `动作 #ID（目录外）`，可照常改/删。

## 3. 方案取舍（四轮演进，作者逐轮截图评审）

- **A（否，一稿）五个分类下拉并排 + 新增按钮**：类型/动作拆两处、无搜索，作者否（"列表
  只显示动作名称就行，不要时间"；"默认先显示一行，设置后自动生效下方自动补一行"）。
- **B（否，二稿）两级联动原生 select**（选择类型→选择动作）：动作下拉一次只见一个类型的
  名单，观感"类型/动作不完整"；原生 select 无搜索能力。
- **C（否，三稿）单 select + optgroup 分组平铺**：全部动作平铺在一个菜单内，不搜索、不能
  分级收起，作者否（"不是全显示…可搜索…选类型后再弹出类型下的动作列表"）。
- **D（选定，四稿）自绘 dd 组件**：原生 select 不支持搜索/两级弹出，自绘 DOM 弹层。点开
  第 1 级类型列表（六组+数量）→ 选类型弹第 2 级该类型动作列表（顶部搜索框按动作名子串
  过滤、sticky 固定 +「‹类型」返回）；点动作即提交；同时只开一个弹层、点外部自动关闭。

## 4. 数据链（口径单源在 QuickAction）

| 环节 | 设计 |
|---|---|
| 产出 | QuickAction v1.8.0 每会话表就绪后写一次 `BepInEx\QuickActionCatalog.txt`（先于首次 Apply，During 还是官方原值）。行格式 `ID\|名称\|分类\|原耗时毫秒` |
| 分类 | 1物品使用 2家具功能 3房屋维护 4杂项交互 5娱乐锻炼（=五分类开关口径）+ **6野外与其他**（引用轴漏网的 Other 玩家动作） |
| 过滤 | Apply 覆盖分支的全部前置守卫：表外结算收益（OutsideGainIds）/周期正收益/纯消耗拦 Outside8/瞬时哨兵（During≤0）/禁改类（Rest=2·Social=5）/无名行——**列进来的动作覆盖一定生效** |
| 读取 | ModCenter `ActionCatalog.cs`：LastWriteTimeUtc 缓存（快照 MC_OPEN/MC_SET 后高频重建不重复读盘），分类容忍 1..6，缺文件/空表 = null |
| 快照 | `ModInfo.acts:[{id,n,c,ms}]`（Payload 手写 JSON；null/空不输出——协议向后兼容，老 panel.js 无感） |
| 回退 | 无 acts → 面板回退旧渲染 + ID 手输框（旧 dll / 首次运行且总开关关） |

## 5. 下拉交互定稿（四稿）

- **行结构**：每条覆盖行 = [dd 按钮（当前动作名）] + 滑条 + 数值框 + ⚡立即生效 + ✕；按钮
  下方保留 `其他.Overrides · id:ms` 对账小字。尾部恒置一行未设置行（按钮占位"选择动作…"，
  右侧提示"选完动作自动添加（默认 1000ms）"）。
- **第 1 级**：六组类型列表，各组带动作数（现算自 acts）。空组不显示。
- **第 2 级**：该类型动作列表（只显示动作名）+ 顶部搜索框（input 逐键子串过滤，display 隐藏
  保滚动位置；sticky 固定不随滚动）+「‹类型」返回。
- **提交语义**：尾行（kind=new）选动作 → push `{id, ms:1000}` → renderCfg + ovrCommit →
  toast「已添加 …=1000ms（滑条可调）」，下方自动补新空行；已覆盖行（kind=pick）换动作 →
  保留该行毫秒 → toast「已改为 …」；与他行重复 → 提示拒绝并复位；选本身（未变）→ 仅复位。
- **弹层管理**：全局同时只开一个（开新先 closeAll）；点击 dd 以外区域自动关闭；renderCfg
  重建后弹层自然复位关闭。
- **性能**：弹层打开时才按类型构建列表（单类型最多约 2700 项一次渲染，搜索为 O(n) display
  过滤）——不做虚拟化。
- **目录外兜底**：acts 查不到的旧 ID，按钮显示 `动作 #ID（目录外）`，照常可改/删。

## 7. 兼容与部署

- 协议向后兼容：`acts` 缺省不输出，老 panel.js 无感；写路径/键名零改动。
- **部署前提**：面板出全量名单（约 3800 条）需要 **QuickAction 与 ModCenter 两个 dll 都换
  新并重启游戏**；只换 ModCenter 时无目录文件，面板自动回退 ID 手输框。判断标志 =
  `BepInEx\QuickActionCatalog.txt` 是否生成。
