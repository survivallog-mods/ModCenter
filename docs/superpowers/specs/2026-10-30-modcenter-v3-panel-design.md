# ModCenter 面板 v3（文案精简 · 冲突两级 · 更新链重做）设计文档

> 日期：2026-10-30 · 作者拍板（会话内逐条确认） · 状态：**定稿，待实施**
> 可视定稿 = `SurvivalLog.ModCenter/prototype.html`（本 spec 的逐字文案与布局均以它为准）。
> 本文档实施完成后，其结论并入 `SurvivalLog.ModCenter/DESIGN.md`（该文件仍是长期活文档）。

## 1. 意图与背景

面板 v2 的提示信息堆术语（启动清理器 / pending / Harmony 账本 / owner / 写序类），冲突
三级（红/橙/灰）用户分不清轻重，独立"套件仓库"页承载了本该融进列表与详情的更新动作。
作者 2026-10-30 两条指令：

1. **提示信息尽量精简、一目了然**——短句、白话、无内部术语；**冲突分两级**：
   严重（明确有问题，只能二选一/多选一）与普通告警（只是可能有问题）。
2. **取消独立更新页**——顶部一个「检查更新」按钮即可；更新按钮融入列表（图标）或
   详情（按钮）；**按钮一律不进左侧 mod 列表**。后续补充拍板：「重装当前版本」入口
   随仓库页退役，需要时先卸载再安装。

## 2. 目标 / 非目标 / 反目标

**目标**
- 全部玩家可见文案（toast/横幅/弹窗/悬停提示/图例）精简到一眼能懂，术语清零。
- 冲突呈现两级：**严重**（红 ⚠）与**普通告警**（橙，⇄脚本碰撞 / ◎功能叠加靠字形区分）。
- 更新动作三入口：顶部「检查更新」、列表行内图标（点击直接确认）、详情页「维护」区按钮。

**非目标**
- 不改任何生命周期机制（pending.json / 清理器 / 壳 / 排序 / 卸载链路原样）。
- 不改消息协议结构（无新增必填字段；MC_REPO_DATA 照推——图标与维护区仍靠它驱动）。
- 不动版本号（作者定号，硬规则 1；本重构随下一次作者定版发版）。

**反目标（出现即失败）**
- 精简后丢失关键事实：不可拦截告警（D7 回退 / D8 版本不符）必须仍以红字出现在确认弹窗。
- 旧面板配新 C#、新面板配旧 C# 出现乱码或图标语义错位（兼容纪律，§6）。
- 原型与 panel.js 不一致入库（同步纪律：同一次提交内一致）。

## 3. 方案取舍

- **A（选定）一次到位**：C# 文案/协议 + panel.js 渲染 + 夹具一个波次改完，逐场景 CDP
  实测。理由：项目纪律本就要求"原型与 panel.js 同提交一致"；分步会产出中间态
  （灰橙混显、文案两套）还要养过渡逻辑。
- B（否）分两步先 C# 后面板：每步可单独进游戏验，但周期翻倍、过渡层纯弃件。

## 5. 详细设计

### 5.1 冲突两级化（C#：Meta.cs / ConfigBridge.cs / PatchScan.cs）

- **色级**：`IcInfo.K` 只产出 `red | orange | blue | amber`；原 `gray` 不再产出。
  ◎ 字形一律带 `G="◎"`（旧面板 `icGlyph` 先认 `g`，兼容）。`click:"cf"` 语义不变。
- **行内提示（Tip）逐字**：
  - L1 严重（红⚠）：`TipShort`（表字段，见 5.2 表）。
  - L2 碰撞（橙⇄，每行聚合一枚）：`脚本碰撞 ×{N}：与{对方显示名}，点看详情`
    （N=组数；对方=组内其他 owner 显示名，取前 2 个，多余省略）。
  - L3 叠加（橙◎）：`功能叠加：{域}类 mod 效果会叠加，点看详情`。
  - L1 波及行（命中他人冲突的套件行）：同该条 `TipShort`。
- **cf 弹窗卡片**（C# 拼装字段语义调整；panel 渲染见 5.4）：
  - `tag` 取值只有 `严重冲突 | 脚本碰撞 | 功能叠加`；
  - `title` = 一句话结论；`reason` 可空（空则面板不渲染"原因"段）；`tips` = "怎么办"编号列表；
  - `lv` 只有 `red | orange`（gray 卡分支删除，"同域 mod"标题逻辑删除）；
  - 弹窗底部固定风险文案删除（各卡已自含）。
- **PatchScan 汇总**：`MC_SCAN_DATA` 结构不变；`items[].owners[]` / `frameItems[].owners[]`
  改为**显示名**（复用 `PatchScan.OwnerDisplay`：套件中文名（En）/ 第三方插件名 /
  `未知来源（id）`）；未知组标注串删除（显示名已自明）。扫描证据文件格式不动。

### 5.3 更新链重做（C#：ConfigBridge.cs；panel.js）

- **保留**：MC_OPEN 打开自动查一次（15 分钟会话缓存）+ MC_CHK 手动查（60 秒冷却）+
  12 仓 fetch + MC_REPO_DATA 推送 + 串行下载链 + MD5 双层校验 + pending 写入——机制全不动。
- **删除**：仓库视图渲染（panel.js `repoViewHtml`/`repoRowHtml`/`lastCheckText`、`ST.repo`
  状态、`data-ract="back|chk|updall|repogoto"` 分支）；C# `MC_UPDALL` 分支与
  `HandleUpdAll`（协议退役，DESIGN.md §3 记录）；ok 行「重装当前版本」与
  `repoVerbOf` 重装分支（D3）。
- **新增**：面板头部「检查更新」按钮（`__mc-btn` 常规款，`margin-left:auto` 靠右）。
  JS 记 `chkWaiting` 标记，`MC_REPO_DATA` 到达时若在等待则推汇总 toast（D8）。
- **详情「维护」区**（新增 `maintHtml(m)`，替代原"维护动作"行；`__self` 页保留仅卸载的
  `uninstActHtml`）：
  - 仓库行 `pending` → 文本 `⟳ 待生效 · 重启游戏后应用`；
  - `update/downgrade/install` 且 `Remote != null` → 按钮（更新到 X=pri / 安装 X=blue /
    降级到 X=org）+ 灰字 `未安装 → {remote}` 或 `{local} → {remote}`；
  - 非 missing 才有「卸载…」行（tp 与套件一致——链上第三方有专门卸载路由；hint=`删文件，重启后生效`）。
- **行内图标 Tip 逐字**（ConfigBridge 产出）：
  - update（蓝↑）：`可更新：{local} → {remote}`
  - downgrade（橙↓）：`可降级：本地 {local} 比远端 {remote} 新`
  - 版本告警 ⊘（橙，G=kbw）：`可能不适配当前游戏版本`
  - 待生效 ⟳（琥珀，无 click）：`待生效：重启游戏后应用`
  - （实施修正：未装行不产 ↑ 图标——C# RepoIcsOf 从不为 Install 态产图标（v2 同口径），
    安装入口只有详情「维护」区按钮。）
